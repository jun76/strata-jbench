### 1. レコードの構造

このデータセットは、テキストベースのフラットファイル（または行ベースのログ）として構成されています。各レコードは以下の要素で構成されています。

**形式:**
`recordID: content`

**具体例 (record000001):**
*   **ID:** `record000001`
    *   固定長（7文字）の文字列。
    *   接頭辞 `record` + 6桁の数字（ゼロ埋め）。
    *   数値的に順序付けられています。
*   **区切り文字:** `:` (コロン) とスペース。
*   **内容 (Content):** `alpha beta gamma delta epsilon zeta eta theta.`
    *   8つの単語（ギリシャ文字）で構成される固定内容。
    *   末尾にピリオド `.` があります。
    *   **重要な性質:** すべてのレコードの内容が完全に同一である（重複データ）。

**データ特性:**
*   **順序性:** レコードは ID の昇順（1から212）で並んでいます。
*   **均一性:** 内容が完全に同じため、情報的な多様性はありません。これは「テストデータ」または「圧縮可能なデータ」として扱われることが多い構造です。

### 2. ID からレコードを探す手順

ID が既知の場合（例: `record000150` を探す）、以下の手順で検索します。

#### A. 単純な線形検索 (Linear Search)
最も基本的な方法ですが、データ量が大きくなると非効率的です。

1.  ファイルを上から順に読み込む。
2.  各行の先頭部分（ID）を抽出する。
3.  抽出した ID が目標 ID (`record000150`) と一致するまで比較を続ける。
4.  一致したら、その行の残り部分（内容）を返す。

**計算量:** O(N) （N はレコード数）
