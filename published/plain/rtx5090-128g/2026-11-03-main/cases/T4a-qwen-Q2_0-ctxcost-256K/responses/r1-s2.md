### 1. レコード構造の分析

#### 構造概要
```
[recordID]: [field1] [field2] ... [field8]
```

#### 構成要素
1. **ID (Key)**: `record000001` 形式。
   - 固定長さ（12文字）の文字列。
   - 数字部分は 6桁（000001〜000212）。
   - **特徴**: ID 自体が数値順序（Lexicographic order = Numeric order）で排列されている。
2. **Value (Payload)**: `alpha beta gamma delta epsilon zeta eta theta`
   - 8つのトークン（単語）から構成。
   - **重要**: 全てのレコードで Value 内容が**完全同一**。

#### 隐含の特性
- **重複性**: Value 部分に差異がないため、Value による検索は効率的ではありません（全レコードが同じ）。
- **ID の単調性**: ID 番号は 1から212まで連続整数で構成されている。

---

### 2. IDからレコードを探す基本手順

件数が212件程度であれば、以下の「基本方法」で十分高速ですが、件数が数万〜数百万に増えた場合、以下の手順では**O(N)** 時間复杂度（線形時間）となり、性能瓶颈になります。

#### 手順 A: 線形探索（Linear Search）
1. 全てのレコードをリストとして読み込み。
2. 目標ID（例: `record000150`）を指定。
3. 1番目から順にIDを比較。
4. 一致するID found then return Value.

**問題点**:
- 平均で N/2 回の比較が必要。
- 212件なら問題ないが, 100万件なら数秒〜数分かかる可能性。
