## 1. レコードの構造の説明

### 1.1 基本结构

Each record has the following structure:

```
recordID: content
```

- **recordID**: 8-digit zero-padded number.  
  - Format: `record000001`, `record000002`, ..., `record000212`  
  - ID range: `record000001` to `record000212` (inclusive).  
  - Total records: **212 records**.

- **content**: Always the same fixed string:  
  ```
  alpha beta gamma delta epsilon zeta eta theta.
  ```  
  - This is a static payload (no variation between records).

### 1.2 特徴

- **Uniformity**: All records have identical content.
- **Sequential IDs**: IDs are strictly sequential integers from 1 to 212.
- **Fixed-width ID format**: Always 6 digits after “record” (e.g., `record000001`).
- **No metadata beyond ID and payload**.

---

## 2. ID-to-record search procedure (basic)

Given an ID like `record000001`, how to find its content?

### 2.1 Naive method (linear scan)

1. Read all records in order from `record000001` to `record000212`.
2. Compare each ID to the target ID.
3. When match is found, return content.

**Time complexity**: O(n)  
**Space complexity**: O(1) if streaming, O(n) if storing all.

### 2.2 Better method (direct calculation)

Since IDs are sequential and zero-padded, you can compute the offset:

- Parse ID string `recordNNNNNN` → extract integer N.
- Compute position = N - 1 (0-based index).
- If records are stored in an array, access `array[position]`.

This is **O(1)** lookup.
