以下、提示されたレコード群の構造、ID からレコードを探す手順、件数増加時の高速化工夫をできるだけ詳しく説明します。

---

## 1. レコードの構造

### 1.1 全体フォーマット

各レコードは次のような 1 行テキストです。

```text
record000001: alpha beta gamma delta epsilon zeta eta theta.
```

これを分解すると、以下の 3 要素に分けられます。

| 要素 | 例 | 説明 |
|---|---|---|
| ID 部分 | `record000001` | レコードを一意に識別する識別子 |
| 区切り | `: ` | ID と本文を分ける区切り文字（コロン + 半角スペース） |
| 本文 | `alpha beta gamma delta epsilon zeta eta theta.` | 8 個のギリシャ文字名が半角スペースで並び、末尾にピリオド |

つまり一般形は次のように表せます。

```text
record<6桁の連番>: alpha beta gamma delta epsilon zeta eta theta.
```

---

### 1.2 ID の構造

ID は `record` + 6 桁の零埋め十进制数です。

```text
record000001
record000002
...
record000212
```

特徴：

- 接頭辞は常に `record`
- 数値部分は常に 6 桁
- 1 から始まる
- 今回のデータでは `record000001` から `record000212` まで連続
- 欠番なし
- 重複なし

零埋めされているため、辞書順（文字列順）に並べても数値順になります。

例：

```text
record000009 < record000010 < record000100 < record000212
```

もし零埋めでなければ、

```text
record9, record10, record100
```

は辞書順では

```text
record10 < record100 < record9
```

となり、直感とずれます。零埋めはこの問題を防ぐための重要な設計です。
