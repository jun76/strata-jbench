以下、ご提示のデータ（record000001〜record000212）の構造、IDからレコードを探す手順、そして件数が増えたときに高速に探すための工夫を、できるだけ詳しく説明します。

---

## 1. レコードの構造の詳細

### 1.1 全体フォーマット

各レコードは以下の形をしています：

```
recordNNNNNN: alpha beta gamma delta epsilon zeta eta theta.
```

- `record` という固定プレフィックス
- 6桁のゼロ埋め整数（`NNNNNN`）
- コロン `:` と半角スペース 1つ
- 8つのギリシャ文字名が半角スペースで区切られたリスト
- 末尾にピリオド `.`

### 1.2 各部分の意味

| 要素 | 内容 | 説明 |
|---|---|---|
| プレフィックス | `record` | レコード種別を示す固定文字列 |
| ID | `000001`〜`000212` | 6桁ゼロ埋めの連番。1から始まり、1ずつ増加 |
| 区切り | `: ` | IDと本文を分離。コロン＋スペース |
| 本文 | `alpha beta gamma delta epsilon zeta eta theta` | 常に同じ8トークン。順序も固定 |
| 終端 | `.` | 文末記号。全レコードで同一 |

### 1.3 IDの特徴

- **ゼロ埋め（zero-padding）**
  - `record000001`, `record000002`, … `record000212`
  - 6桁なので、字典順（文字列順）と数値順が一致する
  - 例：`record000009` < `record000010` < `record000100` < `record000212`
- **連続性**
  - 欠番なし（000001〜000212まで全て存在）
  - 総件数 = 212件
- **接頭辞が同じ**
  - 全レコードが `record` で始まるため、検索時にプレフィックスを除けば純粋な数値として扱える
