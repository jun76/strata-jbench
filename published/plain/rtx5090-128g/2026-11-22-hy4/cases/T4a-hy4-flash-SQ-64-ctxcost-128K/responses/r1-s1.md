以下、ご提示のデータ（record000001 ～ record000212）の構造、IDから該当レコードを探す手順、そして件数が増えた場合に高速検索するための工夫を、できるだけ詳しく説明します。

---

## 1. レコードの構造の詳細

### 1.1 全体形式

各レコードは以下の形をしています：

```
recordNNNNNN: alpha beta gamma delta epsilon zeta eta theta.
```

| 要素 | 内容 | 説明 |
|---|---|---|
| ID部分 | `record000001` ～ `record000212` | `record` + 6桁のゼロ埋め整数 |
| 区切り | `:`（コロン）+ 半角スペース1つ | IDと本文の境界 |
| 本文 | `alpha beta gamma delta epsilon zeta eta theta.` | 8つのギリシャ文字名が半角スペースで区切り、末尾にピリオド |
| 改行 | 1レコード = 1行 | 各行は独立 |

### 1.2 IDの特徴

- `record` という接頭辞 + **6桁固定幅**
- ゼロ埋め（zero-padding）がされている
  - `record000001`
  - `record000009`
  - `record000010`
  - `record000100`
  - `record000212`
- そのため **文字列としてソートしても数値順と一致する**
  - `record000099` < `record000100` < `record000101` の順になる
  - もし `record99` のようにゼロ埋めでないと `record100` より後ろに来てしまう

### 1.3 本文の構造

本文は常に同じトークン列です：

| 位置 | トークン |
|---|---|
| 1 | alpha |
| 2 | beta |
| 3 | gamma |
| 4 | delta |
| 5 | epsilon |
| 6 | zeta |
| 7 | eta |
| 8 | theta |

- 区切り：半角スペース（1文字）
- 末尾：`.`（ピリオド）
- 大文字・小文字：すべて小文字
- トークン数：ちょうど 8 個
- 文末ピ
