以下、ご提示いただいたレコード群の構造、ID からレコードを探す手順、件数が増えた場合の高速化工夫について、できるだけ詳しく説明します。

---

## 1. レコードの構造

### 1.1 全体形式

各レコードは次のような 1 行テキストです：

```
record000001: alpha beta gamma delta epsilon zeta eta theta.
```

これを分解すると：

| 要素 | 内容 | 説明 |
|---|---|---|
| ID 部分 | `record000001` | レコードを一意に識別する識別子 |
| 区切り | `:`（コロン） | ID と本文を分離する区切り文字 |
| 本文 | ` alpha beta gamma delta epsilon zeta eta theta.` | 8 個のギリシャ文字由来のトークン + 末尾のピリオド |

---

### 1.2 ID の構造

- 接頭辞：`record`
- 数字部分：`000001` ～ `000212`
- 桁数：**6 桁のゼロ埋め（zero-padding）**

例：

| ID | 数値 |
|---|---|
| `record000001` | 1 |
| `record000009` | 9 |
| `record000010` | 10 |
| `record000099` | 99 |
| `record000100` | 100 |
| `record000212` | 212 |

#### ゼロ埋めの重要な性质

- 文字列としてソートしても、数値順と一致する
  - `"record000009" < "record000010"` ✅
  - もしゼロ埋めがなければ `"record9" > "record10"` になってしまう ❌
- 固定長なので、バイト位置やオフセット計算が容易

---

### 1.3 本文の構造

本文は常に同じです：

```
alpha beta gamma delta epsilon zeta eta theta.
```

| 位置 | トークン |
|---|---|
| 1 | alpha |
| 2 | beta |
| 3 | gamma |
| 4 | delta |
| 5 | epsilon |
| 6 | zeta |
| 7 | eta |
| 8 | theta |

- 区切り：半角スペース 1 個
