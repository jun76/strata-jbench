以下、提示されたレコード群の構造、ID からレコードを探す手順、そして件数が増えた場合に高速に検索するための工夫について、できるだけ詳しく説明します。

---

## 1. レコードの構造の説明

### 1.1 全体フォーマット

各レコードは以下のような 1 行のテキストです：

```
record000001: alpha beta gamma delta epsilon zeta eta theta.
```

これを分解すると、以下の 3 つの要素で構成されています。

| 要素 | 内容 | 例 |
|---|---|---|
| ① ID 部分 | `record` + 6 桁のゼロ埋め整数 + `:` | `record000001:` |
| ② 区切り | コロン `:` の直後に半角スペース 1 つ | `: ` |
| ③ 本文 | 8 つのギリシャ文字名が半角スペースで連結され、末尾にピリオド | `alpha beta gamma delta epsilon zeta eta theta.` |

### 1.2 ID の特徴

- 接頭辞：`record`
- 数字部分：6 桁固定（例：`000001`, `000212`）
- ゼロ埋め（zero-padding）されている
  - 1 → `000001`
  - 212 → `000212`
- 末尾にコロン `:` が付く

つまり、ID は **辞書順（文字列順）＝数値順** になるよう設計されています。

> 例：  
> `record000009` < `record000010` < `record000100` < `record000212`

これは非常に重要で、文字列ソートしても数値順が崩れません。

### 1.3 本文の特徴

本文は常に同一です：

```
alpha beta gamma delta epsilon zeta eta theta.
```

- トークン数：8
- トークン一覧（順番固定）：

| 位置 | トークン |
|---|---|
| 1 | alpha |
| 2 | beta |
| 3 | gamma |
| 4 | delta |
| 5 | epsilon |
| 6 | zeta |
| 7 | eta |
| 8 | theta |

- 末尾に `.`（ピリオド）
