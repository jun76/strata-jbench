### 1) What the records are
Each record is a structured entry that contains:
- An ID (a unique identifier)
- A name/label
- A timestamp or creation time
- A state/status (e.g., “active”, “pending”, “completed”)
- A category or type
- Optional metadata (e.g., notes, tags, owner, priority)

The records are usually stored in a database or in a file-based format. They can be indexed so that you can find a record quickly by its ID.

### 2) Steps to find a record from its ID
A typical lookup process looks like this:

1. **Read the ID**
   - You start with an ID, such as a numeric identifier or a unique string.

2. **Check the lookup method**
   - If the records are stored in a database, you query the database using the ID.
   - If the records are stored in a file or list, you scan or search the records for the matching ID.

3. **Compare the ID**
   - Compare the ID you provide with the ID stored in each record.

4. **Return the matching record**
   - If a match is found, return that record.
   - If no match is found, return an “not found” result.

5. **Handle the result**
   - If the record exists, display or process it.
   - If it does not exist, report that the ID is unknown or invalid.

### 3) Ways to search quickly when the number of records increases
As the number of records grows, a simple linear scan becomes slow. Better search methods include:

#### A. Use an index
Create an index on the ID field. This allows the system to jump directly to the record instead of scanning every entry.

#### B. Use a hash table
Store records in a hash table where the ID is used as the key. This gives very fast lookup, often close to constant time.

#### C. Use a sorted structure
If the records are sorted by ID, use binary search or a balanced search tree. This is faster than a full scan.
