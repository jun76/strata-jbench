レコードの構造は、ID とその ID に対応する同一の文字列（alpha beta gamma delta epsilon zeta eta theta）からなる単純な対応です。

ID からレコードを探す手順は、まず ID をキーとして使い、レコード集合の中でそのキーと一致する要素を検索することです。ここでは ID が一意で、レコード内容は同じなので、探索は主に ID の一致判定に依存します。

件数が増えたときに速く探す工夫は、レコードを ID 順やハッシュ順に整理し、二分探索やハッシュテーブルを使うことです。たとえば、ID をソートした配列に格納すれば、二分探索で比較的速く探せます。あるいは ID をキーとするハッシュ表を作れば、平均的に非常に速い検索ができます。さらに、レコード内容が同じなら、内容そのものではなく ID だけを索引として管理する方が効率的です。

このように、ID を軸にした索引付けと検索構造を用意することで、件数が増えても探索コストを抑えられます。
