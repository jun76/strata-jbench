レコードの構造は、各レコードが「ID」と「内容」から成り立っています。IDは `record000001` のように、先頭に `record` と、番号を 6 桁にゼロ埋めした文字列が続く形式です。内容は `alpha beta gamma delta epsilon zeta eta theta` という 8 個の単語からなる列です。

ID からレコードを探す手順は次のようになります。

1. 探したい ID を確認する。たとえば `record000042` なら、ID 文字列をそのまま使う。
2. レコード一覧を走査し、ID が一致する行を見つける。
3. 見つかった行の内容部分を取り出す。

この例では、全レコードの内容が同じなので、どの ID を探しても内容は同じです。

件数が増えたときに速く探す工夫は、ID をキーとして索引を作ることです。たとえばハッシュテーブル、辞書、マップなどに `ID -> レコード` の対応を保存しておけば、先頭から順に探す必要がなくなります。ID をキーとして直接検索できるので、探索はほぼ一定時間で行えます。

もう少し具体的には、次のような処理になります。

- レコードを読み込むときに、ID をキーにして `{ID: レコード}` の対応表を作る。
- 検索時には、ID を使ってその対応表からレコードを取り出す。
- 対応表に ID が存在すれば、そのレコードを返す。
- 存在しなければ、「見つからない」と返す。

この方法なら、件数が増えても毎回すべてのレコードを比較する必要はありません。
