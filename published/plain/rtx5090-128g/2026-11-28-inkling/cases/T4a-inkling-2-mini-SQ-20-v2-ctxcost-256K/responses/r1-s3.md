レコードの構造は、ID（record000001 など）とその後に続く 8 つの語（alpha beta gamma delta epsilon zeta eta theta）という単純なテキスト形式です。各レコードは独立した行として並んでおり、ID と語列が 1 対 1 で対応しています。

ID からレコードを探す手順は、まず目的の ID を特定し、その ID に対応する行を順番に走査して一致するものを見つける、という基本形です。たとえば record000042 を探す場合、record000001 から順に読み進め、ID が record000042 の行を見つけた時点でその行の語列を取得します。人間が目視で確認する場合は、ID の番号順に追うか、目印として ID の桁や並びを使って絞り込みます。

件数が増えたときに速く探す工夫としては、まず ID に順序性や規則性を持たせ、ID をキーとして扱うことが重要です。単純なテキスト一覧では、ID の文字列比較やソートを利用して探索範囲を絞れます。さらに、ID とレコード本文を別々に管理し、ID から本文への参照を索引化すると、全件を毎回読まずに済みます。たとえば ID をキー、レコード内容を値とする辞書やハッシュテーブルに変換すれば、探索は概ね一度のキー検索で済みます。

大量件数では、さらに次のような工夫が有効です。

- ID をソート済みの順序で保持する  
  ID が番号順で並んでいる場合、二分探索を使えば全件走査より速く探せます。

- ID をキーにした索引を作る  
  レコード本体を別ファイルや別領域に置き、ID と位置や参照だけを索引として持てば、検索時に本体を全部読む必要がなくなります。
