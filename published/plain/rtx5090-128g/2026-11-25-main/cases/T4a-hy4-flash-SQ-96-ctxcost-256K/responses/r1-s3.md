## 1. レコードの構造の説明

### 1.1 各行のフォーマット

各レコードは以下の形式で記述されています：

```
record000001: alpha beta gamma delta epsilon zeta eta theta.
```

これを分解すると：

| 要素 | 内容 | 説明 |
|---|---|---|
| レコードID | `record000001` | 固定長 6 桁の連番を持つ識別子 |
| 区切り | `:` (コロン + 半角スペース) | ID と本文を分離 |
| 本文 | `alpha beta gamma delta epsilon zeta eta theta.` | 8 つのギリシャ文字名が半角スペースで並び、末尾にピリオド |

### 1.2 ID の特徴

- 接頭辞：`record`
- 数字部分：`000001` ～ `000212`（現在の確認範囲）
- 数字は **ゼロ埋め 6 桁**（zero-padded）
  - 例：`1` → `000001`、`212` → `000212`
- 連番であり、飛び番号は見受けられません（少なくとも 1～212 は連続）

### 1.3 本文の特徴

- 常に同じ 8 トークン：

  ```
  alpha, beta, gamma, delta, epsilon, zeta, eta, theta
  ```

- 順序も常に同一
- 末尾に `.`（ピリオド）が付与
- 内容は **完全に同一**（可変情報は ID のみ）

つまり、このデータセットは：

> 「キー（ID）だけが異なり、値（本文）はすべて一定である連想配列」

と捉えることができます。

### 1.4 構造の模式化

```
recordNNNNNN: TOKEN1 TOKEN2 ... TOKEN8.
```

- `N` = 数字（6桁）
- `TOKENi` = 固定語彙
