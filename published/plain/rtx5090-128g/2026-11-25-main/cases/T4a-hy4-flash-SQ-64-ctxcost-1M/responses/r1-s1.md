以下、ご提示のデータ（record000001〜record000212）の構造、IDからレコードを探す手順、件数が増えたときの高速検索の工夫について、できるだけ詳しく説明します。

---

## 1. レコードの構造

### 1.1 全体形式

各レコードは次の形をしています：

```
record000001: alpha beta gamma delta epsilon zeta eta theta.
```

これは以下のように分解できます：

| 要素 | 内容 | 説明 |
|---|---|---|
| ID部分 | `record000001` | レコード識別子。接頭辞 `record` + 6桁のゼロ埋め番号 |
| 区切り | `:`（コロン） | IDと本文を分離 |
| 本文 | `alpha beta gamma delta epsilon zeta eta theta.` | 8つのギリシャ文字名が半角スペースで並び、末尾にピリオド |
| 改行 | 各行1レコード | 1行 = 1レコード |

### 1.2 IDの詳細

- `record` は固定接頭辞
- 後続の数字は **6桁のゼロ埋め（zero-padding）**
  - `000001` → 1
  - `000212` → 212
- したがって、IDは文字列としてソートしても数値順と一致する

```
record000001
record000002
...
record000009
record000010
...
record000099
record000100
...
record000212
```

⚠️ もしゼロ埋めでなければ、文字列ソートで `record100` が `record99` より前に来てしまうため、ゼロ埋めが重要です。

### 1.3 本文の詳細

本文は常に同じ：

```
alpha beta gamma delta epsilon zeta eta theta.
```

- トークン数：8語
- 区切り：半角スペース 1つ
- 末尾：`.`（ピリオド）
- 語順：ギリシャ文字のアルファベット順（alpha, beta, gamma, delta, epsilon, zeta, eta, theta）

つまり、**本文はすべてのレコードで完全に同一**です。
