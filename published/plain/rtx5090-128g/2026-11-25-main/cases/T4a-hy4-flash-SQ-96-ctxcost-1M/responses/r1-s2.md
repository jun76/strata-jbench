## 1. レコードの構造の説明

### 1.1 全体形式

各レコードは以下のような固定形式のテキスト行です：

```
record000001: alpha beta gamma delta epsilon zeta eta theta.
```

これを分解すると：

| 要素 | 内容 | 説明 |
|---|---|---|
| レコードID | `record000001` | 先頭に付与された一意な識別子 |
| 区切り | `:` | IDと本文を分離する区切り文字 |
| 本文 | `alpha beta gamma delta epsilon zeta eta theta.` | 8つのギリシャ文字名が半角スペースで並び、末尾にピリオド |

### 1.2 IDの構造

- 接頭辞：`record`
- 数字部分：6桁のゼロ埋め整数（`000001` ～ `000212` まで確認）
- 書式：`record` + `%06d`（例：`record000212`）

つまり、IDは **連番であり、辞書順＝数値順** になるよう設計されています。

> ✅ `record000010` < `record000011` < … < `record000100` の順は、文字列比較でも正しく並びます。

### 1.3 本文の構造

本文は常に同一です：

```
alpha beta gamma delta epsilon zeta eta theta.
```

| 位置 | トークン |
|---|---|
| 1 | alpha |
| 2 | beta |
| 3 | gamma |
| 4 | delta |
| 5 | epsilon |
| 6 | zeta |
| 7 | eta |
| 8 | theta |

- トークン数：8
- 区切り：半角スペース（1つ）
- 末尾：`.`（ピリオド）
- 改行：各行末尾にある（LF または CRLF）

### 1.4 データの特徴

- **すべてのレコードの本文が完全に同一**
- IDのみが異なる
- 極めて高い冗長性を持つ（同じ文字列が212回繰り返し）
