以下、提示されたレコード群の構造、ID からレコードを探す基本手順、そして件数が増えた場合に高速に探すための工夫を、できるだけ詳しく説明します。

---

## 1. レコードの構造の説明

### 1.1 各行のフォーマット

すべての行は以下の完全一致パターンです：

```
recordNNNNNN: alpha beta gamma delta epsilon zeta eta theta.
```

具体的には：

| 要素 | 内容 | 詳細 |
|---|---|---|
| ID 部分 | `record000001` 〜 `record000212` | 固定長 6 桁のゼロ埋め整数が `record` に続く |
| 区切り | `:` + 半角スペース 1 つ | `record000001:` の直後に空白 |
| 本体 | `alpha beta gamma delta epsilon zeta eta theta.` | 8 つのギリシャ文字名が半角スペースで連結され、末尾にピリオド |
| 改行 | LF（想定） | 各行 1 レコード |

### 1.2 構造的な特徴

- **ID は連番**：`000001` から `000212` まで 1 ずつ増加（欠番なし）
- **ID の桁数は固定 6 桁**：`1` は `000001`、`212` は `000212`
- **本体は全行同一**：情報量は ID のみ（本体は定数文字列）
- **ソート済み**：ID の昇順に並んでいる（重要：二分探索が使える）
- **レコード数**：212 件（確認済み）

### 1.3 正規表現で表すと

```regex
^record(\d{6}): (alpha beta gamma delta epsilon zeta eta theta)\.$
```

- キャプチャ 1：数値 ID（文字列）
- キャプチャ 2：固定本文

### 1.4 データとして捉え直すと

実質的に次のような辞書／配列と等価です：

```text
index = 1..212
value = "alpha beta gamma delta epsilon zeta eta theta."
```

つまり **「キー＝連番、値＝定数
