以下、提示されたレコード群の構造、ID からレコードを探す手順、件数増加時の高速化工夫について、できるだけ詳しく説明します。

---

## 1. レコードの構造

### 1.1 全体形式

各レコードは 1 行で表され、以下の構造を持っています。

```
record<6桁の連番>: <トークン列>.
```

具体的には、例として：

```
record000001: alpha beta gamma delta epsilon zeta eta theta.
```

が挙げられます。

---

### 1.2 構成要素の分解

| 要素 | 内容 | 説明 |
|---|---|---|
| レコード ID | `record000001` | `record` + 6 桁のゼロ埋め整数 |
| 区切り | `:` | ID と本体を分離 |
| 空白 | 1 個 | 可読性のための区切り |
| 本体 | `alpha beta gamma delta epsilon zeta eta theta` | 8 個のギリシャ文字名トークン |
| 終端 | `.` | レコード末尾を示すピリオド |

---

### 1.3 ID の特徴

- 形式：`record` + 6 桁十进制数
- 例：
  - `record000001`
  - `record000212`
- 連番は 1 から始まり、提示データでは `record000212` まで確認できます。
- ゼロ埋めにより、辞書順ソートが数値順と一致する点が重要です。

```
record000009 < record000010 < record000100 < record000212
```

これは文字列比較でも正しい順序になります。

---

### 1.4 本体トークンの構造

本体は常に同じ 8 トークンです。

| 位置 | トークン |
|---|---|
| 1 | alpha |
| 2 | beta |
| 3 | gamma |
| 4 | delta |
| 5 | epsilon |
| 6 | zeta |
| 7 | eta |
| 8 | theta |

つまり、レコード本体は固定スキーマを持つと言えます。

```
<token1> <token2> ... <token8>.
```

このため、実質的に「可変部分」は ID
