以下、提示されたレコード群の構造、ID からレコードを探す手順、件数が増えた場合の高速化工夫について、できるだけ詳しく説明します。

---

## 1. レコードの構造

### 1.1 全体形式

各レコードは次のような 1 行テキストです：

```
record000001: alpha beta gamma delta epsilon zeta eta theta.
```

これを分解すると：

| 要素 | 内容 | 説明 |
|---|---|---|
| レコード ID | `record000001` | 固定長 6 桁の連番 |
| 区切り | `:`（コロン） | ID と本体を分離 |
| 空白 | 1 つ | 可読性のため（必須ではない） |
| 本体 | `alpha beta gamma delta epsilon zeta eta theta.` | 8 つのギリシャ文字＋末尾ピリオド |
| 改行 | `\n` | レコード境界 |

つまり、一般的な形式は：

```
record{6桁ゼロ埋め連番}: alpha beta gamma delta epsilon zeta eta theta.
```

と表せます。

---

### 1.2 ID の特徴

- 接頭辞：`record`
- 数部：`000001` ～ `000212`（この例では 212 件）
- ゼロ埋め（zero-padding）されている
  - `record1` ではなく `record000001`
- 連番は 1 から始まる
- 辞書順（lexicographic order）＝数値順になる

重要な点：

```
record000009 < record000010 < record000100
```

が普通に成り立つため、**文字列比較だけで正しい順序が保証**されます。  
これは後述の二分探索やインデックス設計で非常に有利です。

---

### 1.3 本体の特徴

本体は全レコードで完全に同一です：

```
alpha beta gamma delta epsilon zeta eta theta.
```

- 単語数：8
- 区切り：半角スペース
- 末尾：`.`（ピリオド）
- 意味上の差分なし

つまり、このデータセットは「**ID だけが異なる固定ペイロードの繰り返し**」です。
