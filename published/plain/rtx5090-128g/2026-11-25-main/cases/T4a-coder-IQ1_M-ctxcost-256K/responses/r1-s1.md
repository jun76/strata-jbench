以下はレコードの構造、IDからレコードの查找（Lookup）手順、および件数増时で速く查找工夫の详细 explanation。

## 1. レコードの構造 (Record Structure)

### 1.1. 基本構造
*   **Format**: `record[6-digit ID]: [8 tokens]`
*   **Delimiter**: Space (` `) between tokens
*   **ID Format**: `record` + 6-digit zero-padded number
    *   Example: `record000001`, `record000100`, `record000212`
*   **Tokens**: 8 Greek letter names (always in order):
    1.  alpha
    2.  beta
    3.  gamma
    4.  delta
    5.  epsilon
    6.  zeta
    7.  eta
    8.  theta

### 1.2. Byte-level Structure (Fixed-width assumption)
Since all records have identical content except for the ID, the structure can be analyzed for optimization:

*   **Prefix**: `record` (6 bytes)
*   **ID**: `000001` to `999999` (6 bytes, numeric string)
*   **Separator**: `: ` (2 bytes)
*   **Content**: `alpha beta gamma delta epsilon zeta eta theta` (45 bytes, including spaces)
*   **Newline**: `\n` (1 byte)
*   **Total per line**: 6 + 6 + 2 + 45 + 1 = **60 bytes** (fixed-width)

### 1.3. Key Properties
*   **Uniformity**: All records have identical token content.
*   **Monotonic ID**: IDs are sequentially incrementing.
*   **Fixed-width**: Due to zero-padding and uniform content, each record occupies exactly the same number of bytes.

## 2. IDからレコードの查找 (Lookup) 手順

### 2.1. Basic Linear Search (Naive)
*   **Algorithm**: Scan from the beginning, compare ID string.
*   **Time Complexity**: O(n)
*   **Use Case**: Only suitable for very small datasets or if data is not sorted/random
