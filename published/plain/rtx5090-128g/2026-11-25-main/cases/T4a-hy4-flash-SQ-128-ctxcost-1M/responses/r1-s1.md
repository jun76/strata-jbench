以下、提示されたレコード群の構造、ID からレコードを探す手順、件数増加時に高速に探すための工夫を詳しく説明します。

---

## 1. レコードの構造

### 1.1 全体形式

各レコードは次のような 1 行テキストです。

```text
record000001: alpha beta gamma delta epsilon zeta eta theta.
```

これを分解すると、以下の 3 要素で構成されています。

| 要素 | 例 | 説明 |
|---|---|---|
| ID 部 | `record000001` | レコードを一意に識別する識別子 |
| 区切り | `: ` | ID と本文を分離する区切り文字（コロン＋半角スペース） |
| 本文部 | `alpha beta gamma delta epsilon zeta eta theta.` | 8 個のギリシャ文字名が半角スペースで並び、末尾にピリオド |

### 1.2 ID 部の構造

ID は次の規則で成り立っています。

```text
record + 6桁のゼロ埋め十进制数
```

例：

| ID | 数値 |
|---|---|
| `record000001` | 1 |
| `record000010` | 10 |
| `record000100` | 100 |
| `record000212` | 212 |

特徴：

- 接頭辞は常に `record`
- 数字部分は常に **6 桁**
- 足りない桁は先頭が `0` で埋められている
- そのため、文字列順に並べると数値順と一致する

つまり：

```text
record000001 < record000002 < ... < record000009 < record000010 < ... < record000212
```

という字典順が、そのまま数値順になります。

これは非常に重要で、後述の高速検索（二分探索など）が正しく動く理由になります。
